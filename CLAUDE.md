# CLAUDE.md — правила разработки LoadLab

LoadLab — образовательная LMS-платформа для обучения нагрузочному тестированию.
Проект долгосрочный и развивается поэтапно.

## Главное правило

**Проект не переписывается с нуля.** Перед любым заданием изучи существующую структуру
и расширяй её, сохраняя работоспособность уже реализованного.

Перед началом работы прочитай:

1. [ROADMAP.md](ROADMAP.md) — какой этап сейчас и что уже сделано.
2. [ARCHITECTURE.md](ARCHITECTURE.md) — как устроена система.
3. [PROJECT_SPEC.md](PROJECT_SPEC.md) — что должна уметь платформа.
4. Для учебного контента: [CURRICULUM.md](CURRICULUM.md) и [docs/TEACHING_METHOD.md](docs/TEACHING_METHOD.md).

## Порядок работы

- Выполняй только тот этап, который указан в задании. Не переходи к следующему без отдельного задания.
- Если видишь проблему в архитектуре — сначала объясни её, и только потом вноси масштабные изменения.
- После работы обнови статусы в ROADMAP.md.
- Не утверждай, что проверка пройдена, если она не выполнялась. Скажи, чего не хватает.
- Объяснения владельцу проекта — простым языком: он знает основы Python и SQL,
  но не имеет большого опыта веб-разработки.

## Команды

Все команды — из корня проекта, если не указано иное.

```bash
# База данных и backend (Docker)
docker compose up -d                       # только PostgreSQL
docker compose --profile backend up -d     # PostgreSQL + backend
docker compose --profile backend down      # остановить всё

# Проверки backend (внутри контейнера, Python 3.12)
docker compose exec backend pytest
docker compose exec backend ruff check .
docker compose exec backend ruff format --check .

# Frontend (из папки frontend)
npm run dev          # запуск для разработки, http://localhost:3000
npm run lint         # ESLint
npm run typecheck    # проверка типов TypeScript
npm run build        # production-сборка
```

Адреса: frontend — `http://localhost:3000`, backend — `http://localhost:8001`,
документация API — `http://localhost:8001/api/v1/docs`.

Порт backend — **8001**: порт 8000 на компьютере владельца занят системной службой Windows.
На компьютере установлен Python 3.10, поэтому backend запускается и проверяется в Docker
(образ на Python 3.12).

## Архитектурные ограничения

- Frontend и backend независимы и общаются **только через HTTP API** (`/api/v1`).
- Frontend не обращается к базе данных. Все вызовы backend — через `frontend/src/lib/api.ts`.
- Слои backend: `api/endpoints` → `services` → `models`/`db`. Логика — в сервисах,
  endpoints только принимают запрос и возвращают ответ.
- Новая область функциональности = новые файлы (модель, схема, сервис, endpoint)
  + одна строка в `backend/app/api/router.py`. См. ARCHITECTURE.md, раздел 3.
- Структура базы меняется только миграциями Alembic.
- Ошибки API — только в едином формате из `backend/app/core/errors.py`.
- AI никогда не меняет опубликованную учебную программу напрямую: только предложения,
  которые подтверждает администратор.

## Качество кода

- Никаких монолитных файлов: один файл — одна ответственность.
- Понятные имена. Код и идентификаторы — на английском; комментарии, документация
  и тексты интерфейса — на русском.
- **Нет фиктивных кнопок и ссылок.** Каждый элемент интерфейса что-то делает.
  Будущие функции помечаются явно («в планах»), а не имитируются.
- **Секреты только в `.env`.** Никаких паролей и ключей в коде, в `.env.example` и в Git.
- Не добавляй зависимость, если задача решается несколькими строками кода.
  Версии зависимостей фиксируются точно (без `^` и `>=`).
- Не дублируй функциональность: сначала поищи существующий компонент или функцию.
- Не усложняй: решение должно быть не сложнее задачи.
- Новая логика backend сопровождается тестами Pytest.
- Перед завершением работы: тесты, линтеры и проверка типов проходят без ошибок.

## Frontend

- Next.js 16 отличается от более ранних версий. Перед использованием незнакомого API
  сверяйся с документацией в `frontend/node_modules/next/dist/docs/` (см. `frontend/AGENTS.md`).
- Цвета — только через токены темы из `globals.css`; любая страница должна выглядеть
  корректно в светлой и тёмной теме.
- Проверяй адаптивность: ширина от 320 px, без горизонтальной прокрутки.
- Базовые элементы — из `components/ui` (shadcn/ui). Для ссылки в виде кнопки:
  `cn(buttonVariants(...), "доп. классы")`.
- Тексты и данные страниц — в `src/content`, не внутри разметки компонентов.

## Git

- `.env`, пароли, ключи, виртуальные окружения, `node_modules`, временные файлы
  и локальные данные базы в Git не попадают.
- Коммиты — только по просьбе владельца проекта.
- **Никакой автоматической отправки в удалённый репозиторий** (`git push` — только по прямой просьбе).

## Учебный контент

- Аудитория: слабые Python и SQL, без Java. Уровень объяснений — 10-й класс.
- Сначала простое объяснение, затем термин. Не больше 3–5 новых понятий за урок.
- Каждый урок — по структуре из 14 блоков; в конце квиз из 10 вопросов с объяснениями.
- Java как язык программирования не преподаётся. Язык скриптов — Python.
- Не обещать гарантированное трудоустройство или экспертный уровень.
