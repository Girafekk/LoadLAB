# CURRICULUM — программа курса «Нагрузочное тестирование с нуля»

Подробная учебная программа основного курса LoadLab.
Методика преподавания и шаблон урока описаны в [docs/TEACHING_METHOD.md](docs/TEACHING_METHOD.md).

> **Статус документа:** утверждённый план содержания. Уроки всех 9 недель
> написаны, включая продвинутый модуль после разбора 586 вопросов (458 из
> собеседований и 128 из PDF/промпта).
> (см. [docs/INTERVIEW_GAP_REPORT.md](docs/INTERVIEW_GAP_REPORT.md)).

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Цель | Подготовить начинающего специалиста по нагрузочному тестированию (Junior Load Tester) |
| Длительность | 9 недель (2 месяца + продвинутый модуль) |
| Нагрузка | **12–15 часов в неделю** (в сумме 108–135 часов) |
| Рекомендуемый ритм | 5 учебных дней по 2–2,5 часа + 1 день на контрольную точку, 1 день отдыха |
| Состав | 9 модулей (недель), 70 уроков, 9 контрольных точек, итоговый проект |
| Основной инструмент | Apache JMeter; k6 — на уровне знакомства |
| Язык скриптов | Python (Java как язык программирования **не изучается**) |

### Начальный уровень ученика

- Python — слабый; SQL — слабый; Java — отсутствует;
- опыт в нагрузочном тестировании — начальный;
- сложные IT-термины заранее не известны: каждый вводится после простого объяснения.

### Что ученик умеет после курса

1. Объясняет, зачем нужно нагрузочное тестирование и где оно находится в процессе разработки.
2. Составляет базовый план нагрузочного тестирования.
3. Понимает HTTP, клиент-серверную архитектуру и основные сетевые понятия.
4. Создаёт, запускает и анализирует тесты в Apache JMeter.
5. Знаком с k6 и понимает, когда его выбирают.
6. Читает основные метрики производительности (RPS, время отклика, перцентили, ошибки, ресурсы).
7. Работает в терминале Linux на базовом уровне.
8. Пишет простые SQL-запросы.
9. Пишет небольшие Python-скрипты для вспомогательных задач.
10. Анализирует результаты испытаний и оформляет отчёт.
11. Объясняет свои действия и отвечает на типовые вопросы собеседования на Junior-позицию.

> **Честно о результате.** Курс не гарантирует трудоустройство и не делает экспертом за два
> месяца. Он даёт практическую базу уровня Junior, с которой можно проходить собеседования
> и продолжать расти на рабочих задачах.

### Как устроена неделя

- **Урок** = одна небольшая тема: около 1,5 часа вместе с практикой и квизом.
- В конце каждого урока — **квиз из 10 вопросов** с разбором ответов.
- Неделя начинается с **разминки-повторения** (15–20 минут, вопросы из прошлых недель).
- Неделя заканчивается **контрольной точкой**: практическое задание + итоговый квиз модуля.
- Порог прохождения квиза — 70 %. Ниже порога тема попадает в список повторения.

## 2. Что изменено в предварительной структуре и почему

Исходный план проверен на полноту и последовательность. Порядок недель сохранён — он логичен:
сначала «как всё устроено», затем инструменты, затем практика и анализ. Внесены дополнения:

| № | Изменение | Причина |
|---|---|---|
| 1 | Неделя 1: добавлены требования к производительности (SLA, SLO) и понятие тестового стенда | Без них непонятно, с чем сравнивать результат теста |
| 2 | Неделя 2: добавлены curl и основы аутентификации (токены) | curl нужен в Linux и при отладке; токены — основа для корреляции на неделе 6 |
| 3 | Неделя 3: добавлена работа с логами (grep, tail) и SSH; SQL-практика продолжается разминками в неделях 4–8 | Linux и SQL за одну неделю — самая плотная часть курса. Навык закрепляется повторением, а не одним подходом |
| 4 | Неделя 4: добавлены установка библиотек (pip, venv) и формат CSV | Результаты JMeter хранятся в CSV (.jtl) — без него не написать скрипт анализа |
| 5 | Неделя 5: добавлены минимум о Java/JVM, Config-элементы (HTTP Request Defaults, Header и Cookie Manager), извлечение данных из ответа (JSON Extractor), запись сценария | Это обязательные части любого реального сценария; экстракторы — база для корреляции |
| 6 | Неделя 6: добавлены think time и pacing, подготовка тестовых данных, запуск без GUI и HTML-отчёт, хранение скриптов в Git | Тест без пауз и запуск из GUI — две самые частые ошибки новичков |
| 7 | Неделя 7: добавлены связь метрик между собой, обзор Grafana/Prometheus, база данных как узкое место | Поиск узких мест невозможен без понимания, как метрики влияют друг на друга |
| 8 | Сквозное повторение: разминка в начале каждой недели | Интервальное повторение — без него темы недель 2–4 забудутся к неделе 8 |

**Риск плана.** Недели 3 и 4 дают много нового материала ученику со слабыми SQL и Python.
Это учтено: в них меньше теории на урок, больше практики, а закрепление вынесено
в разминки следующих недель. Если ученик не укладывается в 15 часов, эти две недели
допустимо растянуть до трёх — общая логика курса не нарушится.

## 3. Программа по неделям

### Неделя 1. Введение в IT и нагрузочное тестирование

**Цель недели:** понять, чем занимается нагрузочный тестировщик и какие бывают тесты.
**Нагрузка:** ~12 часов. Неделя намеренно лёгкая — ученик привыкает к ритму.

| № | Урок | Практика |
|---|---|---|

| 1.2 | Жизненный цикл разработки и тестирования: SDLC и STLC | Расставить этапы в правильном порядке, найти место нагрузочных тестов |
| 1.3 | Виды тестирования: функциональное и нефункциональное | Классифицировать 12 проверок по видам |
| 1.4 | Зачем нужно нагрузочное тестирование: цели, задачи, цена ошибки | Разобрать 3 реальные истории отказов под нагрузкой |
| 1.5 | Виды нагрузочных тестов: Load, Stress, Spike, Soak | По графику нагрузки определить вид теста; подобрать тест под ситуацию |
| 1.6 | Требования к производительности: SLA, SLO, тестовый стенд | Сформулировать измеримые требования для интернет-магазина |
| 1.7 | Словарь нагрузочного тестировщика: пользователь, запрос, транзакция, RPS, время отклика | Собрать собственный глоссарий из 20 терминов |

**КТ-1:** итоговый квиз (20 вопросов) + задание «Опиши своими словами, какие тесты и зачем
нужны сервису доставки еды перед праздниками».

## 5. Сквозные линии курса

- **Повторение.** Разминка в начале недели берёт вопросы из всех прошлых модулей,
  в первую очередь из слабых тем ученика.
- **SQL и Python после «своих» недель.** В неделях 5–8 они используются в практике:
  подготовка тестовых данных запросами, разбор результатов скриптом из КТ-4.
- **Один учебный стенд.** Практика недель 5–8 идёт на одном учебном приложении
  (интернет-магазин), чтобы ученик узнавал систему всё глубже.
  Стенд — обязательное условие для этих недель: он создаётся отдельным этапом 8
  в [ROADMAP.md](ROADMAP.md), до написания контента (этап 9). Уроки и практика недель 5–8
  пишутся под уже работающий стенд, а не наоборот.
- **Подготовка к собеседованию.** С недели 1 в каждом уроке есть блок
  «Как об этом спрашивают на собеседовании» (1–2 вопроса).

## 6. Вне основной программы («Дополнительный уровень»)

Темы, которые важны, но выходят за рамки Junior-курса даже после недели 9.

- Gatling, Locust и другие инструменты.
- CI/CD и автоматический запуск нагрузочных тестов.
- Глубокий анализ плана SQL (EXPLAIN) и проектирование индексов.
- WebSocket, gRPC и другие протоколы помимо HTTP.
- Kafka Streams, exactly-once и внутреннее устройство брокера.
- Java как язык разработки: курс даёт только минимум для JMeter и JVM.
