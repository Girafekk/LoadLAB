# Проверка перед запуском — простая инструкция

Этот файл для владельца проекта, без глубоких технических знаний.
Выполняйте по порядку. Если пункт не получается — пришлите мне текст ошибки
или скриншот, я подскажу.

---

## 1. Настоящий TLS-сертификат (замок в браузере)

**Что это:** чтобы сайт открывался по `https://ваш-домен.ru`, а не с предупреждением.

**Что нужно заранее:**
- купить домен (например, `loadlab.ru`);
- направить домен на IP сервера (A-запись в панели регистратора);
- открыть на сервере порты 80 и 443.

**Что сделать:**
1. В файле `.env` на сервере заменить:
   ```env
   SITE_ADDRESS=loadlab.ru
   PROD_PUBLIC_URL=https://loadlab.ru
   PROD_CORS_ORIGINS=https://loadlab.ru
   CADDYFILE=./Caddyfile.prod
   ```
2. Перезапустить прокси:
   ```bash
   docker compose -p loadlab-prod -f infrastructure/docker-compose.prod.yml up -d --force-recreate proxy
   ```
3. Подождать 1–2 минуты и открыть `https://loadlab.ru` в браузере.

**Успех:** замок в адресной строке, нет предупреждения «Не защищено»;
`https://loadlab.ru/api/v1/health` показывает `"database":"ok"`.

**Если не получается:** это задача хостинга. Напишите в поддержку:
«Нужно выпустить Let's Encrypt сертификат для домена и настроить HTTPS».
Caddy обычно делает это сам, если DNS уже указывает на сервер.

## 2. Резервная копия с шифрованием

**Что это:** копия базы, из которой можно восстановить сайт.

**Простой вариант:** включить ежедневные backup у хостинга и проверить
восстановление в панели хостинга. Это лучше, чем ручной скрипт.

**Если делаем сами:**
1. На сервере установить GPG:
   ```bash
   sudo apt update && sudo apt install -y gnupg
   ```
2. Создать ключ для backup (спросит имя и email — можно служебные):
   ```bash
   gpg --quick-generate-key "LoadLab Backup" rsa2048 encr 1y
   ```
3. Узнать email/ID ключа:
   ```bash
   gpg --list-keys
   ```
4. В `.env` добавить:
   ```env
   BACKUP_GPG_RECIPIENT=email-из-ключа
   ```
5. Сделать копию:
   ```bash
   ./infrastructure/backup.sh /srv/loadlab/backups
   ```
6. Скопировать файл `.dump.gpg` в другое место: S3, Яндекс Диск, другой сервер
   (не на тот же диск, иначе при поломке сервера пропадёт всё).

**Успех:** в `/srv/loadlab/backups` появился файл `loadlab-....dump.gpg`,
он не пустой; файл лежит ещё и во внешнем хранилище.

**Восстановление:** попросите хостинг или меня помочь — команда destructive,
её лучше не запускать без второй пары глаз:
```bash
./infrastructure/restore.sh backups/loadlab-....dump.gpg
```

## 3. Две вкладки браузера

**Что это:** проверка, что старый экран не пишет данные в новый аккаунт.

**Что сделать:**
1. Откройте **два окна обычного браузера** (не инкогнито), чтобы cookie были общие.
2. В первом войдите как ученик A.
3. Во втором войдите как ученик B.
4. Вернитесь в первое окно — оно должно показать «Сессия изменилась» и
   попросить войти заново, а не молча работать под B.
5. Попробуйте в первом окне старую форму конспекта: она не должна сохранить
   текст в B.
6. Выйдите из A в первом окне и проверьте, что B во втором остался в системе.

**Успех:** старый экран не сохраняет данные в новый аккаунт; выход из старой
вкладки не выкидывает новую.

**Что прислать:** 3–4 скриншота по шагам.

## 4. Зависший парсер

**Что это:** загрузка «тяжёлого» PDF/DOCX не должна вешать сайт навсегда.

**Что сделать:**
1. Возьмите большой скан- PDF (например, 100–200 страниц) или PDF с картинками.
2. Откройте `/admin/interview`, загрузите файл.
3. Засеките время.

**Успех:** через ~30 секунд появляется понятная ошибка «Извлечение текста
превысило лимит времени», сайт продолжает работать, повторная загрузка
обычного TXT проходит.

**Если файл обработался за 5–10 секунд:** это не ошибка, просто парсер не
завис. Можно попробовать файл больше.

## 5. Одновременная сдача

**Что это:** два финальных ответа не должны создать две разные оценки.

**Что сделать:**
1. Начните mock-интервью, дойдите до последнего вопроса.
2. Откройте это же интервью во второй вкладке.
3. Нажмите «Ответить» почти одновременно в двух вкладках.
4. Откройте отчёт.

**Успех:** в отчёте один финальный ответ и один балл; вторая вкладка получает
понятное сообщение, а не вторую оценку.

**Что прислать:** скриншот отчёта и сообщение второй вкладки.

## 6. Живой DeepSeek

**Что это:** проверка, что AI-преподаватель реально отвечает через провайдера.

**Что сделать:**
1. На сервере в `.env` должен быть `DEEPSEEK_API_KEY=...` (ключ не присылать мне).
2. Перезапустить backend:
   ```bash
   docker compose -p loadlab-prod -f infrastructure/docker-compose.prod.yml restart backend-prod
   ```
3. Открыть `/trainers`, задать вопрос: «Что такое p95 простыми словами?».
4. Посмотреть, что в ответе/статусе указан DeepSeek, а не локальный режим.

**Успех:** ответ по смыслу про p95, в интерфейсе нет ключа, в ответе нет
персональных данных.

**Что прислать:** скриншот ответа (ключ и личные данные не нужны).

## 7. Нагрузка 50 пользователей

**Что это:** проверка, что сайт не падает при одновременной работе.

**Что сделать на сервере (или на своём компьютере):**
```bash
python tools/load_test.py https://loadlab.ru 50 60
```
Во время теста во втором терминале:
```bash
docker stats --no-stream
```

**Успех:** в ответе скрипта `"errors": 0`, `p95_ms` меньше 300,
`p99_ms` меньше 500; контейнеры не падают, память не растёт бесконечно.

**Что прислать:** JSON-вывод скрипта и скриншот `docker stats`.

**Если p95 больше 300:** пришлите JSON, разберём. Для учебного проекта
допустимо до 500–700 мс, но лучше понять причину.
