# Задание на ревью: этапы 10–11 и ИИ-чат DeepSeek

Ревьюер: независимая проверка по коду и живому поведению. Не доверяй отчётам
в документации и не считай зелёные тесты доказательством корректности.
`SAVE_SESSION.md` в снимок не передаётся.

Проверяем **все свежие этапы**: 10 (тренажёры), 11 (AI Teacher) и встроенный
ИИ-чат DeepSeek. Этапы 7–9 проверяются только на регрессии, перечисленные ниже.

## 0. Сверка снимка

1. Вызови `loadlab_review_info`.
2. Зафиксируй HEAD, число записей и SHA-256.
3. Прочитай этот файл и ROADMAP/PROJECT_SPEC.
4. Если HEAD не совпадает с ожидаемым в сообщении владельца — остановись
   и сообщи о расхождении.

## 1. Требования этапа 10

Источник: ROADMAP, PROJECT_SPEC 3.6, CLAUDE.md, docs/TEACHING_METHOD.md.

- HTTP-тренажёр: метод и путь, проверка, подсказка.
- SQL-тренажёр: только безопасный SELECT, ограничение результата, проверка.
- Linux-тренажёр: виртуальная ФС, pwd/ls/cat/grep/tail, cwd.
- Анализ: RPS, p95, точка насыщения, разбор.
- Доступ только после входа; 401/422; ошибки не выглядят как бесконечная загрузка.
- `/trainers`: вкладки, формы, результат, 320 px, темы, клавиатура.

## 2. Требования этапа 11 и DeepSeek

- Вопрос по опубликованному уроку; черновик → 404.
- Ответ опирается на материал урока; повторный вопрос объясняет иначе.
- История `ai_teacher_messages`: только своя, каскады, индексы.
- Рекомендации слабых тем и предложение шпаргалки.
- DeepSeek — основной провайдер при `DEEPSEEK_API_KEY`; `deepseek-chat`.
- Без ключа и при сбое провайдера — локальный ответ, без 500.
- `GET /ai/teacher/status` показывает провайдера/модель, но не ключ и не секреты.
- Лимит запросов 429 + `Retry-After`.
- Панель в уроке и блок рекомендаций на `/profile/tools`; 320 px, темы.
- Ответ выводится как текст: без исполнения HTML и без сырого Markdown.

## 3. Критично: изоляция ключа DeepSeek

Проверить любым способом, не раскрывая значение ключа:

1. Ключ есть только в `.env` (или переменных окружения), не в Git, не в
   `.env.example`, не в коде, не в тестах, не в `snapshot.json`, не в логах,
   не в ответах API и не в тексте ошибок.
2. `.env` исключён `.gitignore`; `git ls-files` не содержит `.env`.
3. `GET /ai/teacher/status` отдаёт только `provider`, `model`, `external`.
4. Тесты не делают реальных запросов к DeepSeek: в `tests/conftest.py`
   ключ принудительно пустой; прогон pytest не должен расходовать кредиты.
5. При неверном/просроченном ключе API не падает 500 и не возвращает ключ:
   должен быть локальный ответ или понятная ошибка.
6. В Docker `DEEPSEEK_API_KEY` передаётся из окружения, а не зашит в compose.
7. Проверить `docker compose config` без вывода секрета: ключ подставляется
   из `.env`, но не попадает в репозиторий.

## 4. Безопасность SQL-тренажёра

- Исполнение не в PostgreSQL приложения, а в изолированной SQLite-песочнице.
- Authorizer разрешает только `courses/modules/lessons`; запрещены `users`,
  `sessions`, `ai_teacher_messages`, личные материалы, `sqlite_master`.
- Запрещены запись, `ATTACH`, `PRAGMA`, `setval/nextval`, файловые функции,
  `U&`-идентификаторы.
- Таймаут/`progress_handler` не даёт cross join занять worker.
- Проверить легитимные SELECT, `LIKE`, `COUNT`, подзапросы.
- Проверить 401 на всех 8 маршрутах тренажёров.
- Проверить 429 на SQL (30/мин) и AI (15/мин).

## 5. AI: безопасность и качество

- Prompt injection: инструкции в вопросе не должны менять системную роль.
- В контекст не попадают чужие данные, ключи, сессии, ответы других учеников.
- Ограничение длины вопроса/ответа; HTML не исполняется.
- Проверить поведение без ключа, с таймаутом и с некорректным JSON провайдера.
- Проверить, что повторный вопрос действительно даёт другой ответ, а не только
  другой `mode`.
- Проверить, что локальный режим не выдаёт себя за DeepSeek.

## 6. Регрессии этапов 7–9

- Замена квиза и запись попытки сериализуются; попытка не исчезает.
- `DELETE` квиза требует `confirm_attempts_loss`.
- Прогресс учитывает только опубликованный основной курс.
- Импорт контента не путает уроки после перестановки и не публикует скрытое.
- `--refresh` требует `--confirm` и запрещён в production по эффективным настройкам.

## 7. Команды

```bash
docker compose exec backend ruff check .
docker compose exec backend ruff format --check .
docker compose exec backend alembic check
docker compose exec backend pytest
docker compose exec -T db psql -U loadlab -d loadlab -c "\d ai_teacher_messages"

cd frontend
npm run lint
npm run typecheck
npm run build
```

Живые проверки — на `http://localhost:8001` и `http://localhost:3000`.
Для SQL-атак используй отдельного временного ученика и удали его после.

## 8. Критерии приёмки

- Нет P0/P1.
- Ключ DeepSeek изолирован; тесты не ходят в платный API.
- SQL-тренажёр не читает чужие таблицы и файлы сервера.
- AI не раскрывает чужие данные и не падает без ключа.
- Требования этапов 10–11 выполнены, регрессии 7–9 зелёные.
- Все команды раздела 7 выполнены; если среда не позволяет — это указано.

## 9. Формат ответа

1. Сверка снимка: HEAD, записей, SHA-256.
2. Вердикты: этап 10, этап 11 + DeepSeek, регрессии 7–9.
3. P0–P3 с файлами и строками.
4. Что подтверждено выполнением, что статически, что не проверено.
5. Отдельно: изоляция ключа — подтверждена/нет и чем именно.
6. Сколько вопросов/сценариев реально проверено, без выдачи выборки за всё.
