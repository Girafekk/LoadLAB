# Ручная проверка интерфейса LoadLab

Чек-лист для владельца после этапов 4–6. Браузерные инструменты ревьюеру не нужны:
эти сценарии проверяет человек. Отмечайте результат в последней колонке.

Подготовка:

```bash
docker compose --profile backend up -d
docker compose exec backend alembic upgrade head
docker compose exec backend python -m app.db.seed
npm run dev --prefix frontend
```

Адреса: `http://localhost:3000`, API — `http://localhost:8001/api/v1`.

## 8. Переход между уроками

Сейчас опубликован один урок. Для проверки переноса состояния можно временно
опубликовать второй:

```bash
docker compose exec db psql -U loadlab -d loadlab -c "UPDATE lessons SET is_published = true WHERE id = 2;"
```

| № | Действие | Ожидание | Результат |
|---|---|---|---|
| 8.1 | Пройти квиз урока 1 и перейти на урок 2 | Нет результата и ответов урока 1; квиз урока 2 недоступен, если его нет | |
| 8.2 | Вернуться на урок 1 | Результат урока 1 на месте | |
| 8.3 | Вернуть урок 2 в черновик | `UPDATE lessons SET is_published = false WHERE id = 2;` | |

## Что считать блокером

- Нельзя войти после 401 или вход возвращает к недоступному уроку.
- Виден чужой прогресс, конспект, вопрос или результат квиза.
- Правильные ответы видны до отправки.
- Квиз нельзя пройти из-за старого состояния после перехода между уроками.
- Потеря сохранённого конспекта или шпаргалки без сообщения.
- Горизонтальная прокрутка на 320 px.

Остальное — замечания, которые можно исправить после приёмки.
