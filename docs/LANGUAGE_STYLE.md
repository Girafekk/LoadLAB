# Язык курса и ответов

Аудитория: начинающий нагрузочный тестировщик. Python и SQL — слабые,
Java — не изучается. Человек должен понять тему с первого прочтения, а на
собеседовании — объяснить её своими словами.

## Правила

1. Сначала бытовой пример, затем профессиональный термин.
2. Одно новое понятие — одно-два предложения. Не больше 3–5 новых понятий
   на смысловой блок.
3. Короткие предложения: в среднем 10–18 слов, максимум 25.
4. Термин расшифровывается при первом упоминании: «лаг (lag) — отставание
   обработки».
5. Формула — только после объяснения «зачем». Числа — с пометкой «пример».
6. Не начинать объяснение с определения. Сначала «зачем это нужно».
7. В ответе для собеседования: термин + простое объяснение + пример + граница.
8. Не обещать экспертный уровень и не прятать ограничения.
9. Не использовать слова «очевидно», «просто», «всем известно».
10. Аббревиатуры: RPS, p95, JVM, GC, lag — расшифровать один раз.

## Шаблон ответа на вопрос

> Коротко: <одно предложение простыми словами>.
> Термин: <правильное название и расшифровка>.
> Пример: <что делал на тесте>.
> Вывод: <что это дало и чего не проверяли>.

## Пример

Плохо:

> «Full GC вызывает stop-the-world паузу, что приводит к деградации p95.»

Проще:

> «Full GC — это большая уборка памяти в JVM. На время уборки приложение
> может перестать отвечать, поэтому p95 растёт. Я смотрю паузы GC в логе:
> если они длиннее SLA, проверяю heap и утечки.»

## Границы

Упрощение не отменяет точность: термины, числа и ограничения остаются
профессиональными. Если тема выходит за Junior, это честно написано.
