## 2. Сквозные требования

- Гость: программа видна, урок — 401. Ученик: админка — 403. Чужой ресурс — 404.
- Origin проверяется на изменяющих запросах; CSRF-защита не обходится.
- Пароли/ключи не попадают в Git, ответы API, снимок, логи.
- Черновики не видны ученику; публикация управляется администратором.
- Ошибки API — единый JSON; 401/403/404/409/413/422/429 различимы.
- SQL-песочница не читает личные таблицы и не выполняет запись.
- AI не меняет опубликованную программу без подтверждения администратора.
- Все миграции применяются с нуля; `alembic check` без расхождений.

## 3. Обязательные команды

```bash
docker compose --profile backend up -d
docker compose exec backend pytest -q
docker compose exec backend ruff check .
docker compose exec backend ruff format --check .
docker compose exec backend alembic check
cd frontend && npm run lint && npm run typecheck && npm run build
docker compose -f training_stand/compose.yaml up -d --build
```

Дополнительно:

```bash
docker compose exec backend python -m app.cli export_interview > /tmp/bank.json
python -c "import json; d=json.load(open('/tmp/bank.json')); print(len(d))"
```

Ожидается 586 записей, у всех `lesson_id`, `reference_answer`, `answer_criteria`.

## 4. Ручные сценарии

1. Гость открывает `/learn`, затем `/learn/lessons/1` — 401/вход.
2. Ученик проходит квиз, видит разбор, повторная сдача блокируется.
3. Админ создаёт урок, меняет порядок, публикует; ученик видит изменения.
4. Ученик A и B: A создаёт конспект/интервью, B не видит их.
5. Смена A→B в соседней вкладке: старые данные не остаются на экране.
6. `/trainers`: все четыре вкладки, неверный SQL не читает `users`.
7. `/admin/interview`: загрузка TXT, локальный разбор, подтверждение, привязка.
8. `/mock-interview`: 5 вопросов, ответ, разбор, повтор финального ответа.
9. 320 px, светлая/тёмная тема, Tab/Enter, длинные строки.
