# Задание на независимое ревью этапов 4–6

Документ для ревьюера **LoadLab Reviewer** (GPT-6 Sol Latest). Его задача — проверить
реализацию этапов 4–6 по снимку проекта и дать вердикт, а не переписать код.

---

## 1. Что передаётся ревьюеру

| Параметр | Значение |
|---|---|
| Снимок | `F:\LoadLab-DSH-Review\snapshot.json` |
| SHA-256 и время сборки | в `_REVIEW_SCOPE.md` внутри снимка |
| Базовый HEAD | в `_REVIEW_SCOPE.md`; на момент задания — `c59c551`, ветка `main` |
| Записей | 178+ (текстовые файлы проекта + `_REVIEW_SCOPE.md`) |
| Не входит | `SAVE_SESSION.md`, `.env`, ключи, `.git`, кэши, `node_modules`, `.next`; бинарный `favicon.ico` исключён с SHA-256 в составе |

Инструменты ревьюера: только `loadlab_review_list`, `loadlab_review_read`,
`loadlab_review_search` — чтение снимка. **Запускать тесты, терминал, браузер и Git
ревьюер не может.** Поэтому:

- «проверить функциональные тесты» означает **прочитать тесты, сопоставить их
  с рисками и оценить, что они доказывают**, а не выполнить `pytest`;
- нельзя утверждать «тесты прошли» или «сборка прошла» — это внешние факты,
  которых в снимке нет. Можно писать «тест покрывает сценарий X», «тест не
  проверяет Y», «утверждение из журнала не подтверждается кодом»;
- динамическое поведение (браузер, PostgreSQL-гонки, 320 px) помечается как
  **требует отдельной проверки**, а не как дефект или успех.

Язык отчёта — русский. Файлы не менять, Git-операций не выполнять.

## 2. Бизнес-контекст

LoadLab — образовательная LMS для подготовки Junior Load Tester за 8 недель.
Аудитория: слабые Python и SQL, без Java, уровень объяснений — 10-й класс.
Платформа не обещает трудоустройство или экспертный уровень за два месяца.

Статусы:

- этапы 1–3 — ✅ проверены ранее;
- этапы 4–6 — 🟦 реализованы, ожидают этого ревью и браузерной проверки владельца;
- этапы 7–14 — не начаты (админка, учебный стенд, контент 60 уроков, тренажёры,
  AI Teacher, собеседования, production).

### Цель ревью

Ответить на вопросы:

1. Может ли ученик пройти полный путь «программа → урок → квиз → результат →
   прогресс → личные материалы» без тупиков и обходных действий?
2. Можно ли доверять результатам квиза и прогрессу (нет утечки правильных ответов,
   нет подмены чужого прогресса, нет потери попыток)?
3. Приватны ли конспекты, выделения, вопросы, повторение, шпаргалки и слабые темы?
4. Не выдаёт ли интерфейс нереализованное за работающее и не имитирует ли кнопки?
5. Соответствует ли содержание урока и квиза методике и не проверяет ли квиз
   знание, которого в уроке не было?
6. Готова ли архитектура к этапам 7–9 без переписывания (админка, контент,
   модульные квизы)?

### Бизнес-инварианты

- Гость видит программу, но не содержимое урока и не личный прогресс.
- Ученик не видит и не меняет чужие данные (IDOR).
- Правильные ответы квиза не отдаются до отправки; частичный ответ на вопрос
  с несколькими верными вариантами считается неверным.
- «Урок пройден» — явное действие, а не прокрутка.
- Личные материалы не теряются при удалении урока (кроме конспекта и выделений,
  которые принадлежат уроку).
- Слабые темы отражают лучший результат, а не последний; успешная пересдача
  убирает тему.
- Черновики уроков и квизов не видны ученику.
- Нет фиктивных кнопок: будущее помечено «в планах».
- Тексты простые, без обещаний трудоустройства; квиз проверяет материал урока.

## 3. Правила вердикта и приоритеты

| Приоритет | Значение | Влияние на приёмку |
|---|---|---|
| **P0** | Потеря данных, утечка чужих данных, обход проверки ответов | Не принимать |
| **P1** | Блокирует основной сценарий ученика или нарушает приватность/честность квиза | Не принимать |
| **P2** | Заметное неправильное поведение, есть обходной путь | Принять после исправлений |
| **P3** | Качество, доступность, документация, производительность без текущего влияния | Принять с замечаниями |

Правила:

- вердикт даётся **отдельно по этапам 4, 5 и 6**;
- P0/P1 хотя бы в одном этапе → «не принимать»;
- только P2 → «принять после исправлений»;
- только P3 → «принять»;
- «✅ проверено» не ставится ревьюером: это делает владелец после браузерной
  проверки и исправлений;
- каждое замечание: ID, приоритет, этап, файл и строка, сценарий, ожидаемое и
  фактическое поведение, почему это важно бизнесу, рекомендация;
- отдельно перечислить **предположения**, которые нельзя подтвердить по снимку.

## 4. Технические условия

### Стек и архитектура

- Backend: Python 3.12, FastAPI, Pydantic, SQLAlchemy 2, Alembic, PostgreSQL 17.
- Frontend: Next.js 16 (App Router, `cacheComponents: true`), React 19,
  TypeScript, Tailwind, shadcn/ui.
- Слои: `api/endpoints` → `services` → `models`/`db`; endpoint не содержит логики.
- Frontend общается с backend только через `frontend/src/lib/api.ts`; секретов в
  браузере нет, cookie `HttpOnly`.
- Тексты интерфейса — в `src/content`, данные — из API.
- Новые области — новые файлы и строка в `api/router.py`.

### API

- Все адреса `/api/v1`.
- Единый формат ошибки: `{"error":{"code","message","details"}}`.
- 401 — нет входа; 403 — CSRF/роль; 404 — нет ресурса или черновик; 422 — форма;
  503 — «битый» квиз.
- CSRF: для POST/PUT/PATCH/DELETE обязателен разрешённый `Origin`.
- `user_id` всегда из сессии, никогда из тела или адреса.

### База

- Изменения только миграциями Alembic.
- Имена ограничений `pk_`, `fk_`, `uq_`, `ck_`, `ix_`.
- `lesson_progress` — составной ключ; запись через `ON CONFLICT DO NOTHING`.
- Квиз: ровно один родитель (урок или модуль), уникальность `lesson_id` и
  `module_id`; попытка, ответы и выбранные варианты пишутся одной транзакцией.
- Личные материалы: `CASCADE` по пользователю; `SET NULL` по уроку для вопросов,
  повторения и шпаргалок; конспект и выделения — `CASCADE` по уроку.
- Слабые темы не хранятся: считаются по лучшим попыткам, порог 80 % без округления.

### Frontend и Next.js 16

- `cacheComponents` сохраняет состояние клиентских компонентов при навигации.
  Поэтому состояние, зависящее от урока/ученика, должно сбрасываться ключом
  (`key` включает `lessonId` и `user.id`) или явной логикой загрузки.
- После 401 общая сессия сбрасывается (`clearSession`), иначе страница входа
  вернёт ученика к недоступному уроку.
- Устаревшие ответы не должны перезаписывать новые (номер запроса/ключ).
- Ошибка каталога не должна скрывать уже загруженный урок.
- Контент из API выводится как текст, HTML не исполняется.
- Цвета только через токены; обе темы; ширина от 320 px.

### Сквозные связи

- **Cookie → сессия → пользователь:** `HttpOnly`, `SameSite=Lax`, `Secure` только
  в production; токен в базе — SHA-256; `SESSION_COOKIE_NAME` различается у
  разработки и production-репетиции.
- **CSRF:** глобальная зависимость на `api_router`; проверить, что она действует
  на все изменяющие маршруты, включая новые.
- **401:** `ApiError.status === 401` → `clearSession(version)`; после этого страница
  входа не должна возвращать к недоступному уроку. Сброс применяется только к той
  версии сессии, с которой начался запрос.
- **Смена ученика:** клиент присылает `X-LoadLab-User`; при несовпадении с cookie
  сервер отвечает 409, а вкладки синхронизируются через `BroadcastChannel` и
  перечитывают `/auth/me` при фокусе.
- **Состояние:** смена урока/ученика/версии сессии не переносит результат квиза,
  конспект и черновики; старые ответы не перезаписывают новые.
- **CORS:** разрешён только адрес frontend из `CORS_ORIGINS` и адрес API.

   до этапа 9. Это заявлено в ROADMAP/README.

4. Нет восстановления пароля, подтверждения email, 2FA, входа через сервисы.
5. Ограничитель входа хранится в памяти процесса.
6. Некорректный id урока даёт мягкий 404 (200 + русская страница) из-за потоковой
   отдачи Next.js.
7. Автоматических браузерных тестов нет: только lint/typecheck/build и ручные
   сценарии.
8. Снимок статичен и не включает журнал, `.env`, Git и зависимости.

   сохраняться в состоянии маршрута после выхода (`Cache Components`/`Activity`).
10. Конкурентное сохранение конспекта реализовано через `ON CONFLICT`, но
    отдельного конкурентного теста нет.
11. CORS и cookie настроены для локальной разработки; production-репетиция
    описана отдельно (Caddy, HTTPS, своё имя cookie).
12. `SAVE_SESSION.md` содержит отчёт исполнителя; его утверждения — не
    доказательство, проверяйте код и тесты.
