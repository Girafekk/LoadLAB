## 2. Что сделано на этапе 4

### Backend

- `app/models/lesson_progress.py` — таблица `lesson_progress` с составным
  первичным ключом (`user_id`, `lesson_id`), оба ключа с `ON DELETE CASCADE`.
- `app/schemas/course.py` — контракт каталога, урока и прогресса.

- `app/api/endpoints/lessons.py` — `GET /lessons/{id}` (только после входа),

- `app/db/demo_lesson.py` — демонстрационный урок 1.1 из 14 смысловых частей

- `app/db/seed.py` — после структуры курса публикует демо-урок.
- `app/models/user_session.py` — индексы по `user_id` и `expires_at`.
- `app/api/router.py` — подключены маршруты курсов и уроков.

## 3.2. Итоги второго ревью (GPT-6 Sol Latest, 18.11.2026)

Вердикт: оставить этап 4 в статусе «реализовано», в «проверено» не переводить.
Блокер — повторный вход после истечения сессии со страницы урока. Исправлено:

- **P1.** `AuthProvider` получил `clearSession`: при ответе 401 страница урока
  сбрасывает общую сессию, поэтому страница входа больше не возвращает человека
  к недоступному уроку; адрес возврата сохраняется.
- **P2.** Каталог не показывает старый личный прогресс после выхода: данные
  помечены состоянием входа, под которое загружены, а устаревшие ответы
  отбрасываются по номеру запроса.
- **P2.** Отметка и счётчик разделены: сбой обновления каталога показывается
  отдельным сообщением «отметка сохранена, счётчик обновится позже».
- **P2.** Урок и каталог загружаются независимо: ошибка каталога не скрывает урок,
  пропадает только навигация.
- **P2.** Тест конкуренции переписан: первое соединение держит незакоммиченную
  строку, второй поток ждёт на уникальном индексе, тест проверяет это ожидание.
- **P2.** Ограничитель входа хранит не больше 10 000 ключей и вытесняет самый
  давний за одну операцию, без полного перебора словаря под замком.
- **P2.** У production-стенда своё имя cookie (`SESSION_COOKIE_NAME`), поэтому
  два стенда на `localhost` не затирают сессии друг друга.
- **P3.** Адрес урока принимает только каноническую запись числа; демо-урок
  проверяет наличие блоков запросом; тесты каскадов проверяют сохранность
  чужих отметок; email с управляющими символами даёт 422, а не 500;
  в README production-репетиции добавлена загрузка демо-урока.
- Состав снимка в `_REVIEW_SCOPE.md` теперь считает файлы проекта и сам файл
  состава отдельно — расхождения «манифест против списка» больше нет.

## 3.3. Открытые замечания после второго ревью

- Повторный вход после 401 проверен по коду, но не в браузере: нужен ручной
  сценарий владельца (истёкшая сессия → «Войти» → возврат к уроку).
- Выход при медленном ответе каталога и порядок обновления счётчика также
  требуют браузерной проверки.
- Конкурентный тест выполняется на PostgreSQL и проверяет блокировку, но
  остаётся вероятностным по времени: возможен редкий пропуск окна ожидания.

## 4. Принятые решения

1. Гость видит программу; урок — только после входа (401).
2. «Урок пройден» — явная отметка; прокрутка не считается.
3. Ссылка на урок — по `id`: `/learn/lessons/{lesson_id}`.
4. `user_id` берётся только из сессии — защита от IDOR.
5. Публичный 60-урочный план остаётся в `src/content/curriculum.ts`; API отдаёт
   только опубликованные уроки, поэтому черновики не утекают.
6. Опубликован один демонстрационный урок; остальные 59 — черновики до этапа 9.
7. Квиз в уроке обозначен как план этапа 5, а не имитируется.
