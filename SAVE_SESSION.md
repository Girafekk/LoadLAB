## 3.8. Исправления после ревью GPT-6 Sol (18.11.2026)

Ревью подтвердило снимок `c59c551` и дало вердикт «не принимать до исправлений»
без P0. Исправлено:

- **Смена ученика между вкладками.** `AuthProvider` синхронизирует вкладки через
  `BroadcastChannel`, перечитывает `/auth/me` при фокусе и получает версию сессии.
  Все личные компоненты ключуются по `user.id` и версии. Клиент присылает
  `X-LoadLab-User`; сервер отвечает 409, если cookie уже принадлежит другому
  ученику, поэтому старый экран не запишет черновик в чужой аккаунт.
- **Запоздалый 401.** `clearSession(expectedVersion)` сбрасывает вход только для
  той версии, с которой начался запрос; завершение выхода не трогает новый вход.
- **Разбор квиза.** Варианты блокируются на время отправки, «Ваш выбор» берётся
  из `selected_option_ids` сохранённой попытки, история обновляется только
  актуальным ответом.
- **Позиции ответов.** В демо-квизе верные варианты распределены, а не стоят
  первыми; добавлен тест на отсутствие позиционного шаблона.
- **Бесконечная загрузка каталога.** Ошибка показывается раньше ожидания и
  очищается успешным запросом; каталог привязан к ученику и версии сессии.
- **Медленное сохранение.** Успех применяется только к отправленной версии
  текста; новый конспект, выделение, вопрос, тема или шпаргалка не теряются.
- **Шпаргалки.** На экране появилось редактирование (PATCH).
- **Слабые темы.** Проценты округляются вниз одинаково в квизе и в списке слабых
  тем, поэтому 79,9 % не выглядит как 80 % с противоположными советами.
- **Ошибки авторизации.** 403 больше не выдаётся за «учётная запись отключена»;
  `/auth/me` делает один повтор при временном сбое сети.
- **Валидация текста.** Управляющие символы (включая NUL) отклоняются с 422,
  пустой конспект по-прежнему допустим.
- **`--refresh-demo`.** Запрещён в production; сохраняет прежний флаг публикации
  квиза, а не публикует его заново.
- **История попыток** показывается на экране квиза, а не только в API.
- **Формы входа и регистрации** пересоздаются при смене версии сессии, чтобы

## 4. Принятые решения

1. Гость видит программу; урок — только после входа (401).
2. «Урок пройден» — явная отметка; прокрутка не считается.
3. Ссылка на урок — по `id`: `/learn/lessons/{lesson_id}`.
4. `user_id` берётся только из сессии — защита от IDOR.
5. Публичный 60-урочный план остаётся в `src/content/curriculum.ts`; API отдаёт
   только опубликованные уроки, поэтому черновики не утекают.
6. Опубликован один демонстрационный урок; остальные 59 — черновики до этапа 9.
7. Квиз в уроке обозначен как план этапа 5, а не имитируется.
